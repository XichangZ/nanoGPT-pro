# nanoGPT-shakespeare
It's my learing project from Karpathy's video.I add a tokenizer to improve the model's
ability and the BPC also becoming lower because of the tokenizer.Also, to make the texts
generated by my model better,I changed the datas for training(It's a bigger one now).
I found the importance of bigger datasets.Followings are my best val loss and samples.

## Results
Trained on 5.2 MB of Shakespeare , 3000-token BPE vocabulary,
6 layers / 384 dim / 8 heads (11.9 M parameters), 5000 steps at batch 64 × 256.

| step | train loss | val loss | BPC (bits/char) |
|------|-----------|----------|-----------------|
| 0    | 7.42      | 7.49     | 3.49            |
| 1000 | 3.97      | 4.40     | 2.05            |
| 2500 | 3.26      | 4.03     | 1.88            |
| 4500 | 3.04      | 3.94     | 1.83            |

**BPC = val_loss × tokens_per_char / ln(2)**, with `tokens_per_char = 0.3226`.
During the process, I learned that:
BPC is the only comparable metric across different vocabularies — raw token-level
loss is not, because a larger vocabulary packs more characters per token.

For reference, a character-level model (vocab 65) on the same text reaches
val 1.47 → BPC 2.12. The subword model is better at the same information measure.

## Quick start

```bash
pip install -r requirements.txt

# 1. get the data (public domain, Project Gutenberg #100)
curl -L https://www.gutenberg.org/files/100/100-0.txt -o shakespeare_complete_pg100.txt

# 2. train the tokenizer (writes bpe_merges.txt)
python trainTokenizer.py

# 3. train the model (first run also tokenizes, ~1 h for 5 MB)
python train.py

# 4. generate
python sample.py
```

`train.py` caches the tokenized corpus to `tokens_3000.pt`; delete it if you change
the vocabulary.
